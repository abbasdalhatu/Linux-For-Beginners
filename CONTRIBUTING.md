# Contributing to Linux for Ethical Hackers

Thank you for your interest in improving **Linux for Ethical Hackers**!

This project aims to provide a practical, beginner-friendly Linux learning resource for students, cybersecurity learners, and aspiring ethical hackers. Contributions from the community help make the course more accurate, useful, and accessible.

## How You Can Contribute

You can contribute by:

- Correcting spelling, grammar, or technical errors.
- Improving explanations and examples.
- Adding useful Linux commands and practical exercises.
- Improving existing practical labs.
- Suggesting new learning resources.
- Reporting broken links or outdated information.

## Reporting Issues

If you find an error or something that needs improvement:

1. Open the repository's **Issues** section.
2. Create a new issue.
3. Provide a clear title and description.
4. Include the relevant module, file, or section.
5. Explain the suggested correction where possible.

## Submitting Changes

To contribute directly to the course:

1. Fork this repository.
2. Clone your fork to your computer.
3. Create a new branch for your changes.
4. Make your improvements.
5. Review your changes before submitting.
6. Commit and push your changes.
7. Open a Pull Request explaining what you changed and why.

## Contribution Standards

Please follow these standards when contributing:

- Keep explanations clear and beginner-friendly.
- Ensure technical information is accurate.
- Test commands and practical instructions before submitting them.
- Explain expected results where appropriate.
- Use Markdown consistently.
- Include reliable references for externally sourced information.
- Do not include passwords, API keys, private information, or other secrets.
- Keep cybersecurity exercises within authorized and controlled environments.

## Cybersecurity and Ethical Use

All cybersecurity content must support lawful, responsible, and authorized learning.

Do not submit instructions intended to facilitate unauthorized access, disruption, data theft, or harm.

Practical security exercises should use systems that the learner owns or has explicit permission to test.
