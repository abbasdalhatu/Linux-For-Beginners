## 2. What Is Sudo?

`sudo` stands for **Superuser Do**.

It allows an authorised user to execute commands with elevated privileges.

Normal Linux users have limited permissions. Administrative operations often require additional privileges.

For example, installing software, modifying system configuration, and managing user accounts usually require administrative access.

Without sudo:

```bash
apt update
```

With sudo:

```bash
sudo apt update
```

The second command requests administrative privileges.

---

## 3. Understanding the Root User

The root user is the most privileged account in Linux.

Its UID is always:

```text
0
```

The root account can perform almost any operation on the system.

Examples include:

- Installing and removing software.
- Creating and deleting users.
- Changing system configurations.
- Managing services.
- Modifying file permissions.
- Accessing protected files.

Check your current identity:

```bash
whoami
```

Check your UID:

```bash
id
```

If the UID is 0, you are operating as root.

### Why Not Always Use Root?

Running everything as root is dangerous.

A small mistake can:

- Delete important system files.
- Change critical permissions.
- Damage system configurations.
- Expose sensitive information.

Using a normal account with sudo when necessary reduces accidental damage.

## 4. Basic Sudo Commands

### Execute a Command as Administrator

```bash
sudo command
```

Example:

```bash
sudo apt update
```

### Open a Root Shell

```bash
sudo -i
```

This opens an interactive root login shell.

Exit it with:

```bash
exit
```

Use a root shell only when necessary. Prefer individual sudo commands for routine administration.

### Check Sudo Version

```bash
sudo --version
```

### Check Your Sudo Permissions

```bash
sudo -l
```

This displays the commands your account is authorised to execute through sudo.

---

## 5. Understanding the sudo Group

On Kali and many Debian-based distributions, membership in the `sudo` group normally grants administrative sudo access through the default configuration.

Check the group:

```bash
getent group sudo
```

Check your own group membership:

```bash
groups
```

Check another user's groups:

```bash
groups username
```

### Adding a User to the Sudo Group

Example:

```bash
sudo usermod -aG sudo username
```

This adds the specified user to the supplementary `sudo` group.

Verify:

```bash
id username
```

**Important:** Only grant administrative privileges to trusted users who genuinely need them.

---

## 6. Understanding the sudoers File

Linux uses a configuration file called:

```text
/etc/sudoers
```

It defines which users and groups can execute commands with elevated privileges.

Inspect its permissions:

```bash
ls -l /etc/sudoers
```

Read its contents:

```bash
sudo cat /etc/sudoers
```

Do not edit this file with an ordinary text editor.

Use:

```bash
sudo visudo
```

`visudo` checks the syntax before saving changes, helping prevent configuration mistakes that could lock administrators out of sudo.

### Example Sudoers Rule

A common rule is:

```text
%sudo ALL=(ALL:ALL) ALL
```

Explanation:

| Component | Meaning |
|---|---|
| `%sudo` | The sudo group |
| First `ALL` | All hosts |
| `(ALL:ALL)` | All users and groups |
| Final `ALL` | All commands |

This rule allows members of the sudo group to execute any command as any user or group, subject to the system's sudo configuration.

## 7. Understanding Sudo Authentication

When you execute:

```bash
sudo apt update
```

Linux may request your password.

This is normally the password of your current user, not necessarily the root password.

Sudo may temporarily remember successful authentication, so you might not be prompted for every command.

To check or refresh your authentication timestamp:

```bash
sudo -v
```

To invalidate the cached authentication:

```bash
sudo -k
```

---

## 8. Running Commands as Another User

Sudo can execute a command as another account.

Syntax:

```bash
sudo -u username command
```

Example:

```bash
sudo -u nobody whoami
```

The command executes with the identity of `nobody`, subject to the permissions and restrictions configured on the system.

You can also inspect a command's effective identity:

```bash
sudo -u nobody id
```

This is useful for testing whether a service account has the access it needs.

---

## 9. The Principle of Least Privilege

The principle of least privilege states:

**Every user should receive only the permissions necessary to perform their assigned responsibilities.**

Example:

A student who only needs to read course materials should not automatically receive full administrative privileges.

A database service should not normally run as root when a dedicated service account is sufficient.

Least privilege helps limit the damage caused by mistakes, compromised accounts, and malicious activity.

## 11. Common Sudo Errors

### Error 1: User Is Not in the Sudoers File

Example:

```text
user is not in the sudoers file
```

This means the account is not authorised to use sudo under the current configuration.

An authorised administrator must review and grant the necessary privileges.

### Error 2: Incorrect Password

Possible causes:

- Incorrect user password.
- Keyboard layout mismatch.
- Caps Lock enabled.

### Error 3: Command Not Found

The requested command may not be installed or may not be available in the system's PATH.

Check:

```bash
command -v commandname
```

Replace `commandname` with the actual command.

## 12. Cybersecurity Applications

Sudo is important in Linux security.

### A. Privilege Management

Administrators control who can perform sensitive operations.

### B. Privilege Escalation Awareness

Attackers may attempt to abuse misconfigured sudo permissions to gain elevated access.

### C. Security Auditing

The following command helps administrators inspect sudo permissions:

```bash
sudo -l -U username
```

### D. System Administration

Sudo supports controlled administrative operations without requiring administrators to remain logged in as root.

### E. Incident Investigation

Sudo logs can help investigators understand which privileged commands were executed.

On systems using systemd:

```bash
sudo journalctl -t sudo
```

Log availability depends on the system's logging configuration.
