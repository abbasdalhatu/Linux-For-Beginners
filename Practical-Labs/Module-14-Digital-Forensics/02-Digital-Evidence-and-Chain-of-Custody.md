## 2. What Is Digital Evidence?

Digital evidence is information stored, transmitted, or generated by electronic devices that can help establish facts during an investigation.

Examples include:

- Computer files.
- Emails.
- Browser history.
- System logs.
- Network packet captures.
- Mobile phone messages.
- Photographs and videos.
- Memory contents.
- USB connection records.

### Practical Example

Imagine an organization suspects that confidential information was copied from a company computer.

Potential evidence includes:

1. The original documents.
2. USB connection records.
3. File access timestamps.
4. Windows event logs.
5. Relevant user account activity.
6. Network records.

An investigator examines these sources to determine what happened.

Importantly, an artifact is not automatically proof of wrongdoing. Findings must be interpreted carefully and supported by other evidence where possible.

## 4. Volatile vs Non-Volatile Evidence

This distinction is important during investigations.

### Volatile Evidence

Volatile evidence is data that may disappear when a system loses power or changes state.

Examples:
- RAM contents.
- Running processes.
- Active network connections.
- Temporary runtime information.

### Non-Volatile Evidence

Non-volatile evidence generally remains stored after a device is powered off.

Examples:
- Hard-drive files.
- SSD files.
- USB storage.
- Memory cards.
- Persistent logs.

### Comparison

| Feature | Volatile | Non-volatile |
|---|---|---|
| Persistence | Temporary | Persistent |
| Power loss | May disappear | Usually remains |
| Example | RAM | SSD |
| Collection priority | Often time-sensitive | Depends on circumstances |

**Important:** Do not automatically power off a device during an investigation. Doing so may destroy volatile evidence. Follow an approved forensic response procedure and consider the risks before taking action.

## 5. Evidence Preservation

Evidence preservation means protecting digital information against unauthorized access, modification, deletion, or contamination.

Good preservation practices include:

1. Obtain proper authorization.
2. Record the device's condition.
3. Document the date and time.
4. Assign a unique evidence identifier.
5. Restrict unnecessary access.
6. Use approved acquisition procedures.
7. Calculate cryptographic hashes where appropriate.
8. Store evidence securely.
9. Maintain a chain-of-custody record.

### Example

An investigator receives a USB drive.

The investigator should document:

- Evidence ID: E-002
- Device type: USB flash drive
- Manufacturer and model, if visible
- Physical condition
- Date and time received
- Person who supplied it
- Person who received it

The investigator should not casually open, edit, or delete files on the original device.

## 6. What Is Chain of Custody?

Chain of custody is the documented history of how evidence was collected, transferred, stored, accessed, and handled.

It establishes accountability throughout an investigation.

### Why Is It Important?

It helps demonstrate:

- Who controlled the evidence.
- Where the evidence was stored.
- When it was accessed.
- Whether transfers were documented.
- Whether evidence integrity checks were performed.

Without reliable documentation, it may be difficult to establish that evidence remained properly controlled.

### Example

Consider a USB drive collected during an authorized investigation.

| Time | Person | Action |
|---|---|---|
| 09:00 | Investigator A | Collected USB |
| 09:10 | Investigator A | Assigned evidence ID E-002 |
| 09:30 | Investigator A | Stored device securely |
| 11:00 | Investigator B | Received device |
| 11:15 | Investigator B | Recorded transfer |

Every transfer should be documented.

## 7. Evidence Identification

Every evidence item should have a unique identifier.

Examples:

- E-001: Practice text file.
- E-002: USB storage device.
- E-003: Disk image.
- E-004: Network capture.
- E-005: System log archive.

A unique identifier makes it easier to reference evidence in notes and reports.

### Evidence Register

An evidence register is a structured list of evidence collected during an investigation.

Example:

| Evidence ID | Description | Source |
|---|---|---|
| E-001 | Text file | Practice directory |
| E-002 | USB drive | Authorized collection |
| E-003 | PCAP file | Controlled lab |
| E-004 | Log archive | Practice system |

## 8. Hashing and Evidence Integrity

Hashing helps verify whether a digital file has changed.

Common algorithms:

- SHA-256
- SHA-512

Example:

```bash
sha256sum evidence/sample.txt
```

To save the hash:

```bash
sha256sum evidence/sample.txt > evidence-hash.txt
```

To verify it later:

```bash
sha256sum -c evidence-hash.txt
```

Possible output:

```text
evidence/sample.txt: OK
```

This means the file matches the hash recorded in the checksum file.

A hash does not independently establish the origin or authenticity of evidence. It is one part of a larger evidence-handling process.

---

## 9. Common Evidence-Handling Mistakes

Avoid these mistakes:

### Mistake 1: Modifying Original Evidence

Editing or opening files in a way that changes their contents or metadata may affect the evidence.

### Mistake 2: Failing to Record Evidence Transfers

Every transfer should be documented.

### Mistake 3: Using Weak Documentation

An investigation record should contain clear dates, times, identifiers, and actions.

### Mistake 4: Ignoring Time Zones

Record the time zone used for timestamps. When necessary, preserve the original timestamp and document any normalized time conversion.

### Mistake 5: Treating a Matching Hash as Complete Proof

A matching hash supports integrity verification, but it does not establish who created a file or whether its original collection was lawful.

### Mistake 6: Collecting Evidence Without Authorization

Always work within the approved investigation scope.
