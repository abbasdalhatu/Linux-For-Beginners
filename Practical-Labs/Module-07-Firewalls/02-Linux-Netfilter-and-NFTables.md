# LAB 02: LINUX NETFILTER AND NFTABLES

## 1. Introduction

Linux uses a kernel-level framework called **Netfilter** to control and inspect network traffic.

Netfilter provides the underlying packet-processing capabilities used by Linux firewall tools.

One important tool built around Netfilter is **nftables**.

nftables is a modern Linux framework for managing firewall rules. It provides a unified way to configure packet filtering, network address translation (NAT), and other network traffic controls.

In this lab, we will understand the relationship between Netfilter, nftables, and iptables.

All exercises are inspection-only. We will not modify your existing firewall configuration.

## 3. What Is Netfilter?

Netfilter is a framework inside the Linux kernel that provides facilities for:

- Packet filtering.
- Network address translation.
- Packet modification.
- Connection tracking.
- Network traffic control.

It allows Linux systems to inspect network packets as they move through the networking stack.

For example, when another computer attempts to connect to your Linux machine, Netfilter can evaluate the traffic against firewall rules.

Based on those rules, the packet may be accepted, dropped, or rejected.

## 4. What Is nftables?

nftables is the modern packet-filtering framework used to configure Netfilter.

It replaces the older iptables-based configuration approach in modern Linux firewall administration.

Its main advantages include:

- A unified filtering framework.
- More flexible rule management.
- Improved handling of IPv4 and IPv6.
- Better rule organization.
- Support for sets and maps.
- Efficient rule evaluation.

The main command-line utility is:

```bash
nft
```

For example:

```bash
sudo nft list ruleset
```

This displays the current nftables configuration.

## 5. Netfilter Architecture

Netfilter processes packets at different points in the Linux networking stack.

These processing points are called hooks.

The five important hooks are:

| Hook | Purpose |
|---|---|
| prerouting | Processes packets before routing decisions |
| input | Processes packets destined for the local machine |
| forward | Processes packets passing through the machine |
| output | Processes packets generated by the local machine |
| postrouting | Processes packets after routing decisions |

### Understanding the hooks

**PREROUTING**

A packet arrives at the network interface and passes through this stage before the routing decision.

**INPUT**

A packet destined for your Linux machine is processed here.

Example: Another computer attempts to connect to your SSH service.

**FORWARD**

A packet passing through your Linux machine to another network is processed here.

This is important when Linux acts as a router.

**OUTPUT**

A packet generated by a local application passes through this stage.

Example: Your browser sends a request to a website.

**POSTROUTING**

A packet passes through this stage after the routing decision and before it leaves the system.

This stage is commonly relevant to NAT configurations.

## 6. Understanding nftables Structure

nftables organizes firewall configurations using several components.

### A. Tables

Tables organize firewall rules.

An example table:

```text
inet filter
```

The `inet` family supports both IPv4 and IPv6.

The `filter` name is simply a table name commonly used for filtering rules.

### B. Chains

Chains contain firewall rules.

Examples include:

- input
- output
- forward

### C. Rules

Rules specify what should happen to matching packets.

Examples of actions include:

- accept
- drop
- reject

### D. Expressions

Expressions describe what packets should match.

For example:

- TCP traffic.
- Destination port 22.
- Source IP address.
- Network interface.

## 7. nftables and iptables Comparison

| Feature | nftables | iptables |
|---|---|---|
| Architecture | Modern unified framework | Older command framework |
| IPv4 and IPv6 | Unified inet family available | Traditionally separate tools |
| Rule organization | Tables, chains, sets, maps | Tables, chains, rules |
| Main command | nft | iptables |
| Modern Linux use | Recommended framework | Legacy compatibility remains |

Important: Some systems provide an iptables compatibility interface backed by nftables. Therefore, the presence of both commands does not necessarily mean two independent firewall systems are operating.

## 9. Practical Exercise 2: Inspect Existing Tables and Chains

Display the complete ruleset:

```bash
sudo nft list ruleset
```

Display available tables:

```bash
sudo nft list tables
```

If tables exist, inspect their names.

For each table you identify, note:

- Its family.
- Its name.
- Its chains.
- Any configured rules.

If the output is empty, record that the current nftables ruleset contains no visible rules.

Do not assume that an empty nftables ruleset means the system has no firewall protection. Other firewall tools or mechanisms may be active.

## 10. Practical Exercise 3: Inspect Firewall Backend Information

Check the iptables version:

```bash
sudo iptables --version
```

Look carefully at the output.

You may see something similar to:

```text
iptables v1.8.x (nf_tables)
```

The `(nf_tables)` part indicates that iptables is using the nftables compatibility backend.

You might instead see another backend identifier.

Check the available iptables alternatives:

```bash
update-alternatives --display iptables
```

If the command reports that no alternatives are configured, simply record that result.

Do not change the selected backend.

### Scenario B: Kali Sends a DNS Request

Relevant Netfilter hook:

**OUTPUT**

### Scenario C: Kali Acts as a Router

Relevant Netfilter hooks:

- PREROUTING
- FORWARD
- POSTROUTING

### Scenario D: Kali Receives an HTTP Request

Another computer sends a request to a web service running locally.

Relevant Netfilter hook:

**INPUT**
