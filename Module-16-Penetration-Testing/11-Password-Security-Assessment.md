# PASSWORD SECURITY ASSESSMENT

## 1. Introduction

Password security assessment is the process of evaluating how passwords are created, stored, managed, and protected against unauthorized access.

Passwords are among the most common authentication methods used to protect:
- Computer systems.
- Email accounts.
- University portals.
- Banking applications.
- Servers.
- Cloud platforms.
- Database systems.

A weak password can expose an entire system to unauthorized access.

### Simple Explanation

Imagine a university portal where every student uses a password.

If a student uses:

`123456`

their account may be easy to compromise.

A security professional evaluates the password policies, password storage mechanisms, authentication controls, and account protection mechanisms to identify weaknesses.

The purpose is to improve security, not to access accounts without permission.

## 2. What Is Authentication?

Authentication is the process of verifying the identity of a user or system.

Common authentication factors include:

| Factor | Meaning | Example |
|---|---|---|
| Something you know | Information you remember | Password or PIN |
| Something you have | A physical or digital possession | Security key or authenticator |
| Something you are | A biological characteristic | Fingerprint or face recognition |

Using two or more different authentication factors is called Multi-Factor Authentication (MFA).

### Authentication vs Authorization

These concepts are different.

**Authentication:** Who are you?

**Authorization:** What are you allowed to do?

Example:

A student logs into a university portal.

- Authentication verifies the student's identity.
- Authorization determines whether the student can view results or modify course registrations.

## 3. Password Strength

Password strength describes how difficult a password is to guess or discover.

A strong password should:
- Be sufficiently long.
- Be unique to each account.
- Avoid predictable personal information.
- Avoid common dictionary phrases.
- Resist automated guessing.
- Be stored securely by the application.

### Weak Password Examples

These are examples of passwords that should not be used:

```text
123456
password
qwerty
admin123
iloveyou
```

### Better Password Practices

Use long, unique passphrases or passwords generated by a trusted password manager.

Example of a fictional passphrase:

```text
River-Copper-Mango-Cloud-47!
```

Do not reuse this example as an actual password.

### Length and Complexity

Length is an important part of password strength.

A long, unpredictable passphrase can be stronger and easier to remember than a short password with complicated substitutions.

For example:

```text
P@ssw0rd
```

is not a good password simply because it contains symbols and numbers.

## 4. Password Entropy

Entropy is a measure of uncertainty or unpredictability.

In password security, higher entropy generally means a password is harder to guess.

For a uniformly random password:

\[
H = L \times \log_2(N)
\]

Where:

- H = entropy in bits.
- L = password length.
- N = number of possible characters at each position.

### Example

Suppose a password contains 10 randomly selected characters from an alphabet of 26 lowercase letters.

\[
H = 10 \times \log_2(26)
\]

\[
H \approx 10 \times 4.7
\]

\[
H \approx 47 \text{ bits}
\]

This calculation assumes every character is independently and uniformly selected.

Real human-created passwords are often less unpredictable than this model assumes.

## 5. Password Hashing

Applications should not normally store passwords as readable plaintext.

Instead, they should use password hashing.

A password hash is a derived value produced by a one-way cryptographic function.

### Example

Original fictional password:

```text
MyExamplePassword
```

The application processes the password using a password-hashing algorithm and stores the resulting hash.

During login:
1. The user enters a password.
2. The application retrieves the stored password hash.
3. The password-hashing algorithm verifies the submitted password.
4. Access is granted or rejected.

A properly designed password system does not need to recover the original password.

### Hashing vs Encryption

| Hashing | Encryption |
|---|---|
| Designed to be one-way | Designed to be reversible with a key |
| Used for password verification | Used to protect recoverable data |
| No decryption operation | Decryption is possible with the correct key |

### Common Password Hashing Algorithms

| Algorithm | Purpose |
|---|---|
| Argon2id | Modern password hashing |
| bcrypt | Password hashing |
| scrypt | Password hashing |
| PBKDF2 | Password-based key derivation |

Fast general-purpose hashes such as MD5 and SHA-1 should not be used alone for password storage.

## 6. Salt and Pepper

### Salt

A salt is a unique random value added to a password before hashing.

Purpose:
- Prevent identical passwords from automatically producing identical stored hashes.
- Make precomputed hash attacks less useful.
- Increase the cost of attacking password databases.

A password-hashing library should normally generate and manage salts automatically.

### Pepper

A pepper is an additional secret value used in password protection.

Unlike a salt, a pepper is kept separately from the password database.

It can provide an additional layer of protection when properly implemented.

## 7. Common Password Attacks

### A. Brute-Force Attack

A brute-force attack attempts many possible password combinations.

Example:

An attacker repeatedly guesses passwords until the correct one is found.

Defensive measures:
- Rate limiting.
- Account lockout or progressive delays where appropriate.
- MFA.
- Strong password policies.
- Monitoring suspicious login activity.

### B. Dictionary Attack

A dictionary attack uses a list of commonly used passwords or words.

Defensive measures:
- Block common and compromised passwords.
- Encourage unique passwords.
- Use password managers.
- Apply rate limiting.

### C. Credential Stuffing

Credential stuffing uses previously exposed username-password combinations against other services.

It succeeds when users reuse passwords.

Defensive measures:
- Unique passwords for every service.
- MFA.
- Detection of unusual login patterns.
- Compromised-password screening.

### D. Password Spraying

Password spraying tests a small number of common passwords across multiple accounts.

Defensive measures:
- Block common passwords.
- Monitor authentication failures across accounts.
- Apply rate limiting.
- Use MFA.

### E. Phishing

Phishing tricks users into revealing authentication information through deceptive messages or websites.

Defensive measures:
- Verify website addresses.
- Use phishing-resistant MFA where possible.
- Avoid opening suspicious links.
- Provide security awareness training.

## 8. Password Security Tools

| Tool | Purpose |
|---|---|
| John the Ripper | Password hash auditing |
| Hashcat | Password hash auditing |
| KeePassXC | Password management |
| Bitwarden | Password management |
| OpenSSL | Cryptographic operations |
| Have I Been Pwned | Check whether an email appears in known breaches |

Password-auditing tools should only be used with password hashes you own or have explicit authorization to assess.

Never upload real passwords or sensitive password hashes to unknown websites.

## 9. Password Security Policies

An organization should establish clear password requirements.

Important controls include:

1. Require sufficiently long passwords.
2. Block common and compromised passwords.
3. Encourage unique passwords for each service.
4. Store passwords using appropriate password-hashing algorithms.
5. Require MFA for sensitive accounts.
6. Protect password-reset procedures.
7. Apply login rate limiting.
8. Monitor suspicious authentication activity.
9. Avoid storing passwords in plaintext.
10. Protect administrator accounts carefully.

Avoid forcing frequent password changes without a security reason. Change passwords when compromise is suspected or confirmed.

## 10. Practical Lab: Inspecting Password Hashing

### Objective

Understand the difference between a password and its cryptographic hash.

This exercise uses a fictional test password. Never use your real password.

### Step 1: Create Your Lab Directory

```bash
mkdir -p ~/module16-lab/lesson11
cd ~/module16-lab/lesson11
```

### Step 2: Generate a Test SHA-256 Hash

```bash
printf '%s' 'ExamplePassword123!' | sha256sum
```

Observe the output.

It contains:
- A hash value.
- The input filename or standard-input indicator.

### Step 3: Hash the Same Input Again

```bash
printf '%s' 'ExamplePassword123!' | sha256sum
```

The result should be identical because the input is identical and SHA-256 is deterministic.

### Step 4: Change One Character

```bash
printf '%s' 'ExamplePassword124!' | sha256sum
```

Compare the new hash with the previous hash.

A small input change produces a substantially different hash.

### Step 5: Understand the Limitation

SHA-256 is a general-purpose hash, not a recommended standalone password-storage algorithm.

Real password storage should use a password-hashing algorithm such as Argon2id, bcrypt, scrypt, or PBKDF2 with appropriate parameters.

## 14. Common Password Security Mistakes

1. Using short and predictable passwords.
2. Reusing passwords across services.
3. Storing passwords in plaintext.
4. Using fast general-purpose hashes alone for password storage.
5. Ignoring MFA.
6. Sharing passwords with other people.
7. Saving passwords in unprotected documents.
8. Ignoring compromised-password notifications.
9. Using weak account-recovery procedures.
10. Failing to monitor suspicious login attempts.
