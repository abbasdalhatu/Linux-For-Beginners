# PROJECT 1: NETWORK SECURITY AUDIT

## Objective

Perform a basic security audit of your Kali Linux virtual machine.

You will inspect network interfaces, IP addresses, routing, listening services, and firewall status.

### Step 1: Create the project directory

```bash
mkdir -p ~/module15-lab/project1-network-audit
cd ~/module15-lab/project1-network-audit
```

### Step 2: Identify the operating system

```bash
hostnamectl
```

### Step 3: Inspect network interfaces

```bash
ip -br addr
```

### Step 4: Inspect routing

```bash
ip route
```

### Step 5: Inspect listening services

```bash
ss -tulpen
```

### Step 6: Check firewall tools

```bash
command -v ufw
command -v nft
command -v iptables
```

These commands identify available tools. They do not change firewall settings.

### Step 7: Save your findings

```bash
hostnamectl > system-information.txt
ip -br addr > interfaces.txt
ip route > routing.txt
ss -tulpen > listening-services.txt
```

### Step 8: Write your audit report

Create:

```bash
nano network-security-audit.txt
```

Use this structure:

```text
NETWORK SECURITY AUDIT

1. SYSTEM INFORMATION

Hostname:
Operating System:

2. NETWORK INTERFACES

Interface Names:
IP Addresses:
Interface States:

3. ROUTING

Default Gateway:
Network Routes:

4. LISTENING SERVICES

TCP Services:
UDP Services:

5. FIREWALL TOOLS

Available Firewall Tools:
Firewall Configuration Status:

6. SECURITY OBSERVATIONS

Unexpected Services:
Potential Risks:
Configuration Concerns:

7. RECOMMENDATIONS

8. CONCLUSION
```

### Expected Outcome

A documented overview of your Kali VM's network configuration and potential security concerns.

# PROJECT 2: NETWORK THREAT AND RISK ASSESSMENT

## Objective

Identify common network threats and recommend suitable defenses.

### Step 1: Create the project directory

```bash
mkdir -p ~/module15-lab/project2-threat-assessment
cd ~/module15-lab/project2-threat-assessment
```

### Step 2: Create the threat assessment file

```bash
nano threat-assessment.txt
```

### Step 3: Use this threat register

| Threat | Potential Impact | Recommended Defense |
|---|---|---|
| Phishing | Credential theft | Security awareness and MFA |
| MITM | Traffic interception | TLS and certificate validation |
| DNS spoofing | Redirection | Secure DNS configuration |
| DoS | Service disruption | Filtering and traffic monitoring |
| Rogue DHCP | Incorrect network configuration | DHCP snooping |
| ARP spoofing | Traffic manipulation | Dynamic ARP Inspection |
| Weak Wi-Fi password | Unauthorized access | Strong authentication |
| Unauthorized access | Data exposure | Access control and MFA |
| Malware communication | Data theft | Endpoint and network monitoring |
| VLAN misconfiguration | Network exposure | Secure switch configuration |

### Step 4: Add risk ratings

Use this scale:

```text
LOW
MEDIUM
HIGH
CRITICAL
```

Consider:

- Likelihood.
- Impact.
- Existing security controls.

### Step 5: Write your conclusion

Explain which threats require the highest priority and why.

### Expected Outcome

A threat register showing your ability to identify network risks and recommend defensive controls.

# PROJECT 3: NETWORK TRAFFIC ANALYSIS

## Objective

Use tcpdump to inspect a limited amount of traffic generated by your own Kali VM.

### Step 1: Create the directory

```bash
mkdir -p ~/module15-lab/project3-traffic-analysis
cd ~/module15-lab/project3-traffic-analysis
```

### Step 2: Identify your network interface

```bash
ip -br link
```

### Step 3: Check tcpdump

```bash
command -v tcpdump
```

### Step 4: Capture a small number of packets

Replace `eth0` with your actual interface.

```bash
sudo tcpdump -i eth0 -c 30 -w traffic-analysis.pcap
```

### Step 5: Read the capture

```bash
tcpdump -r traffic-analysis.pcap -nn
```

### Step 6: Display packet counts by protocol

If tshark is installed:

```bash
tshark -r traffic-analysis.pcap -q -z io,phs
```

### Step 7: Inspect DNS packets

```bash
tshark -r traffic-analysis.pcap -Y "dns"
```

If no DNS packets were captured, record that observation.

### Step 8: Create your analysis report

```bash
nano traffic-analysis-report.txt
```

Use:

```text
NETWORK TRAFFIC ANALYSIS REPORT

Capture Interface:

Capture File:

Total Packets:

Protocols Observed:

Source IP Addresses:

Destination IP Addresses:

DNS Activity:

TCP Activity:

Unusual Observations:

Security Interpretation:

Conclusion:
```

### Expected Outcome

A packet capture and a written explanation of the traffic observed.

# PROJECT 4: DNS SECURITY INVESTIGATION

Investigate DNS resolution and document basic DNS security observations.

### Step 1: Create the directory

```bash
mkdir -p ~/module15-lab/project4-dns-investigation
cd ~/module15-lab/project4-dns-investigation
```

### Step 2: Inspect the resolver configuration

```bash
cat /etc/resolv.conf
```

### Step 3: Query a domain

```bash
dig example.com
```

### Step 4: Inspect different DNS record types

```bash
dig example.com A
dig example.com AAAA
dig example.com NS
dig example.com MX
dig example.com TXT
```

Some domains may not publish every record type.

### Step 5: Inspect DNS response details

```bash
dig example.com +noall +answer
```

### Step 6: Save the results

```bash
dig example.com > dns-query.txt
dig example.com NS > dns-nameservers.txt
dig example.com MX > dns-mail-servers.txt
```

# PROJECT 5: SECURE NETWORK ARCHITECTURE DESIGN

## Objective

Design a secure network for a fictional organization.

You will apply your knowledge of segmentation, VLANs, firewalls, wireless networks, and access control.

### Step 1: Create the project directory

```bash
mkdir -p ~/module15-lab/project5-network-architecture
cd ~/module15-lab/project5-network-architecture
```

### Step 2: Define the organization

Organization: Smart University

Departments:

- Administration.
- Finance.
- Students.
- Computer Science Laboratory.
- IT Department.
- Guest Wi-Fi.

### Step 3: Create a VLAN plan

| VLAN | Department | Subnet |
|---|---|---|
| 10 | Administration | 192.168.10.0/24 |
| 20 | Students | 192.168.20.0/24 |
| 30 | Finance | 192.168.30.0/24 |
| 40 | Computer Science Lab | 192.168.40.0/24 |
| 50 | IT Department | 192.168.50.0/24 |
| 60 | Guest Wi-Fi | 192.168.60.0/24 |

These are proposed design values, not actual network configurations.

### Step 4: Define security policies

```text
ADMINISTRATION
- Access authorized administrative applications.
- Restricted access to sensitive financial systems.

FINANCE
- Access authorized financial applications.
- No unrestricted student access.

STUDENTS
- Access approved student services.
- No direct access to administration or finance systems.

COMPUTER SCIENCE LAB
- Access approved educational and laboratory resources.
- Isolate experimental systems where appropriate.

IT DEPARTMENT
- Authorized management access.
- Use MFA and administrative logging.

GUEST WI-FI
- Internet access only.
- No direct access to internal university systems.
```

### Step 5: Design the network architecture

Your design should include:

- Internet gateway.
- Firewall.
- Core Layer 3 switch.
- VLANs.
- Wireless access points.
- Internal servers.
- Guest network.
- Monitoring system.

### Step 6: Document your architecture


Use this structure:

```text

Organization:

5. FIREWALL POLICIES
```

# PROJECT 6: NETWORK SECURITY MONITORING DASHBOARD

## Objective

Create a simple text-based monitoring dashboard using Linux commands.

This project does not require a graphical monitoring platform.

### Step 1: Create the directory

```bash
mkdir -p ~/module15-lab/project6-monitoring-dashboard
cd ~/module15-lab/project6-monitoring-dashboard
```

### Step 2: Create the script

```bash
nano network-dashboard.sh
```

### Step 3: Add the following script

```bash
#!/bin/bash

echo "======================================"
echo "       NETWORK SECURITY DASHBOARD"
echo "======================================"

echo
echo "[1] HOST INFORMATION"
hostname
date

echo
echo "[2] NETWORK INTERFACES"
ip -br addr

echo
echo "[3] ROUTING INFORMATION"
ip route

echo
echo "[4] LISTENING SERVICES"
ss -tulpen

echo
echo "[5] ESTABLISHED CONNECTIONS"
ss -tn state established

echo
echo "[6] NETWORK INTERFACE STATISTICS"
ip -s link

echo
echo "======================================"
echo "       MONITORING COMPLETED"
echo "======================================"
```

### Step 4: Make the script executable

```bash
chmod +x network-dashboard.sh
```

### Step 5: Run the dashboard

```bash
./network-dashboard.sh
```

### Step 6: Save dashboard output

```bash
./network-dashboard.sh > monitoring-report.txt
```

### Step 7: Inspect the report

```bash
cat monitoring-report.txt
```

### Expected Outcome

A working text-based network monitoring dashboard that gathers basic information about your Kali VM.

**Important:** This is a basic information-gathering dashboard, not a real-time IDS or automated threat detection system.

4. Tools used.
