# Module 14 – Lesson 04: iptables Fundamentals

## 1. Introduction to iptables

**iptables** is a command-line utility used to configure packet-filtering rules on Linux systems.

It allows administrators to control how network packets enter, leave, or pass through a Linux machine.

iptables works with the Linux kernel's Netfilter framework.

### Why Is iptables Important?

iptables helps administrators:

1. Allow authorised network connections.
2. Block unwanted traffic.
3. Restrict access to specific ports.
4. Control network traffic by IP address.
5. Implement NAT.
6. Monitor and log network traffic.
7. Protect Linux servers and networks.

### Real-World Example

Imagine a university Linux server that provides an online learning platform.

The administrator may want to:

- Allow HTTPS traffic on port 443.
- Allow SSH only from an authorised management network.
- Block unnecessary incoming connections.
- Prevent unauthorised access to internal services.

iptables can help enforce these policies.

---

## 2. Understanding iptables Architecture

iptables uses three main concepts:

- Tables.
- Chains.
- Rules.

### Tables

A table groups rules according to their purpose.

### Chains

A chain contains an ordered collection of firewall rules.

### Rules

A rule defines the conditions under which traffic is allowed, blocked, rejected, or otherwise processed.

### Simplified Structure

```text
iptables
   |
   +-- Tables
         |
         +-- Chains
                |
                +-- Rules
                       |
                       +-- ACCEPT
                       +-- DROP
                       +-- REJECT
```

---

## 3. Understanding iptables Tables

iptables provides several tables.

### A. Filter Table

The filter table handles ordinary packet filtering.

It contains three main chains:

- INPUT
- OUTPUT
- FORWARD

Example:

```bash
sudo iptables -t filter -L -n -v
```

### B. NAT Table

The NAT table handles Network Address Translation.

Its common chains include:

- PREROUTING
- OUTPUT
- POSTROUTING

Example:

```bash
sudo iptables -t nat -L -n -v
```

### C. Mangle Table

The mangle table is used for specialised packet modifications.

Example:

```bash
sudo iptables -t mangle -L -n -v
```

### D. Raw Table

The raw table is used for operations involving connection tracking.

Example:

```bash
sudo iptables -t raw -L -n -v
```

### E. Security Table

The security table supports additional security-related packet processing where available.

Example:

```bash
sudo iptables -t security -L -n -v
```

Note: The availability of tables and chains depends on the Linux kernel and installed configuration.

---

## 4. Understanding iptables Chains

A chain is an ordered list of rules.

### INPUT Chain

Processes packets destined for the local Linux machine.

Example:

A remote computer connects to the SSH server on your Kali VM.

### OUTPUT Chain

Processes packets generated by the local Linux machine.

Example:

Your Kali VM sends a request to an external website.

### FORWARD Chain

Processes packets passing through the Linux machine.

Example:

A Linux machine routes traffic between two separate networks.

### PREROUTING Chain

Processes packets before the routing decision.

### POSTROUTING Chain

Processes packets after the routing decision.

---

## 5. Understanding iptables Targets

A target determines what happens when a rule matches a packet.

### ACCEPT

Allows matching traffic.

### DROP

Silently discards matching traffic.

### REJECT

Blocks matching traffic and sends a rejection response.

### RETURN

Stops processing the current user-defined chain and returns to the calling chain.

### LOG

Writes information about matching packets to the kernel logging system, then continues rule processing.

Important: LOG is not itself a final traffic decision. A subsequent rule or chain policy determines what happens to the packet.

---

## 6. Understanding iptables Syntax

A common iptables command follows this structure:

```bash
sudo iptables [table] [operation] [chain] [conditions] [target]
```

Example:

```bash
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
```

Explanation:

| Option | Meaning |
|---|---|
| `-A` | Append a rule |
| `INPUT` | Select the INPUT chain |
| `-p tcp` | Match TCP traffic |
| `--dport 443` | Match destination port 443 |
| `-j ACCEPT` | Allow matching traffic |

This is an illustrative rule. Do not execute configuration-changing examples during this lesson.

## 8. Understanding Protocol Filtering

iptables can filter traffic based on network protocols.

### TCP

TCP is connection-oriented.

Common applications include:

- SSH.
- HTTP.
- HTTPS.
- SMTP.

### UDP

UDP is connectionless.

Common applications include:

- DNS.
- DHCP.
- Streaming.
- Voice communication.

### ICMP

ICMP supports network diagnostics and error reporting.

For example, the `ping` utility commonly uses ICMP Echo Request and Echo Reply messages.

iptables can match traffic using:

```bash
-p tcp
```

```bash
-p udp
```

```bash
-p icmp
```

---

## 9. Understanding IP Address Filtering

iptables can filter traffic based on source or destination IP addresses.

### Source IP

The `-s` option matches a source address.

Illustrative example:

```bash
sudo iptables -A INPUT -s 192.168.1.10 -j ACCEPT
```

This allows matching traffic from the specified source address.

### Destination IP

The `-d` option matches a destination address.

Illustrative example:

```bash
sudo iptables -A OUTPUT -d 192.168.1.20 -j ACCEPT
```

This allows matching outgoing traffic destined for the specified address.

These are examples of syntax, not instructions to modify your active firewall.

---

## 10. Understanding Connection Tracking

iptables can use connection-tracking information to make stateful firewall decisions.

Common connection states include:

- NEW
- ESTABLISHED
- RELATED
- INVALID

Example of an illustrative rule:

```bash
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
```

This matches incoming packets associated with established or related connections.

### Why Is Connection Tracking Important?

It allows administrators to distinguish between:

- New connection attempts.
- Traffic belonging to existing connections.
- Traffic related to existing connections.
- Invalid or unrecognised traffic.

This provides more context than filtering every packet independently.

---

## 11. Understanding Rule Order

iptables processes rules in order.

The first matching rule may determine the action, depending on its target.

Consider this conceptual example:

```text
1. Allow trusted SSH traffic.
2. Allow HTTPS traffic.
3. Block other incoming traffic.
```

If an earlier rule matches, later rules may never be evaluated for that packet.

### Important Security Principle

Rule order matters.

An incorrect rule placed before an important security rule may produce unexpected results.

Administrators should inspect the complete ruleset before making changes.

---

## 12. Understanding Default Policies

A chain can have a default policy.

Common policies include:

- ACCEPT
- DROP

Example of an illustrative policy command:

```bash
sudo iptables -P INPUT DROP
```

This sets the INPUT chain's default policy to DROP.

**Warning:** Changing the default policy can immediately interrupt network access, including SSH administration.

Do not execute policy-changing commands during this lesson.

---

## 13. iptables and NAT

iptables supports Network Address Translation.

### SNAT

Changes the source IP address of outgoing packets.

### DNAT

Changes the destination IP address of incoming packets.

### MASQUERADE

A form of source NAT commonly used when an outgoing interface receives a dynamic IP address.

NAT is commonly used in:

- Virtual machine networking.
- Home routers.
- Enterprise gateways.
- Internet connection sharing.

NAT does not replace a properly configured firewall.

---

## 14. Saving and Restoring iptables Rules

iptables rules may be stored and restored using appropriate system tools.

### Save Rules

On systems with `iptables-save`:

```bash
sudo iptables-save
```

This prints the current ruleset.

### Restore Rules

The `iptables-restore` utility can load a saved ruleset.

```bash
sudo iptables-restore
```

This command reads rules from standard input.

Warning: Restoring a ruleset can replace or change active firewall configuration. Do not experiment with it on your working system without a verified backup and recovery plan.
