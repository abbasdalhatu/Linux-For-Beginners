# Module 14 – Lesson 07: Inbound and Outbound Traffic Control

## 1. Introduction

Network traffic control is the process of managing how data enters, leaves, and passes through a computer or network.

A firewall controls traffic based on security rules and policies.

There are three important traffic directions:

1. Inbound traffic.
2. Outbound traffic.
3. Forwarded traffic.

Understanding these directions is essential for Linux system administration and cybersecurity.

---

## 2. Understanding Inbound Traffic

Inbound traffic is network communication entering a computer or server from another device.

### Example

Imagine you have a Linux web server.

A user opens a browser and visits:

```text
https://example.com
```

The browser sends a request to the web server.

That incoming request is inbound traffic from the server's perspective.

### Common Inbound Services

| Service | Protocol | Port |
|---|---|---:|
| SSH | TCP | 22 |
| HTTP | TCP | 80 |
| HTTPS | TCP | 443 |
| DNS | UDP/TCP | 53 |
| SMTP | TCP | 25 |

### Why Control Inbound Traffic?

Controlling inbound traffic helps:

- Prevent unauthorised access.
- Reduce exposed services.
- Protect sensitive applications.
- Limit network attacks.
- Restrict administrative access.

### Example UFW Rule

Illustrative command:

```bash
sudo ufw allow 443/tcp
```

This permits incoming TCP traffic to port 443.

Do not execute configuration-changing examples during this lesson.

---

## 3. Understanding Outbound Traffic

Outbound traffic is network communication leaving a computer or server toward another device.

### Example

Your Linux machine connects to a website to download a software package.

The request travels from your machine to the remote server.

That outgoing communication is outbound traffic.

### Common Outbound Activities

- Visiting websites.
- Downloading updates.
- Sending emails.
- Performing DNS queries.
- Connecting to remote servers.
- Communicating with cloud services.

### Why Control Outbound Traffic?

Outbound filtering helps:

- Prevent malware from communicating with external servers.
- Reduce unauthorised data transfers.
- Control access to external services.
- Enforce organisational network policies.
- Detect suspicious communication.

### Example UFW Rule

Illustrative command:

```bash
sudo ufw deny out 25/tcp
```

This blocks matching outbound TCP traffic to destination port 25.

---

## 4. Understanding Forwarded Traffic

Forwarded traffic passes through a Linux system from one network interface to another.

A Linux machine can act as a router or gateway.

### Example

Imagine a Linux machine connecting:

- An internal university network.
- An external internet connection.

A student computer sends a request to an internet server.

The request enters the Linux gateway through one interface and leaves through another.

The Linux gateway is forwarding the traffic.

### Simple Network Diagram

```text
Student Computer
       |
       | Internal Network
       |
Linux Gateway
       |
       | External Network
       |
Internet Server
```

The Linux gateway can inspect and filter the forwarded traffic.

### Why Control Forwarded Traffic?

- Prevent unauthorised network access.
- Separate internal networks.
- Protect sensitive systems.
- Restrict communication between network segments.
- Enforce network access policies.

---

## 5. Comparing the Three Traffic Directions

| Traffic | Meaning | Example |
|---|---|---|
| Inbound | Enters the local system | SSH connection to a server |
| Outbound | Leaves the local system | Linux downloading updates |
| Forwarded | Passes through the system | Gateway routing student traffic |

Remember:

Traffic direction depends on which system you are examining.

A packet leaving your laptop is outbound traffic from your laptop's perspective, but inbound traffic from the destination server's perspective.

---

## 6. Linux Firewall Chains and Traffic Direction

Linux firewall systems use chains and hooks to process traffic.

### iptables

The filter table commonly uses three important chains:

**INPUT**

Processes packets destined for the local system.

**OUTPUT**

Processes packets generated by the local system.

**FORWARD**

Processes packets routed through the local system.

Example inspection:

```bash
sudo iptables -L INPUT -n -v
sudo iptables -L OUTPUT -n -v
sudo iptables -L FORWARD -n -v
```

These commands display the corresponding chains.

### nftables

nftables uses base chains attached to Netfilter hooks.

Common hooks include:

| Hook | Purpose |
|---|---|
| input | Traffic destined for the local machine |
| output | Traffic generated by the local machine |
| forward | Traffic routed through the machine |
| prerouting | Traffic before routing decisions |
| postrouting | Traffic after routing decisions |

Example inspection:

```bash
sudo nft list ruleset
```

---

## 7. Controlling Inbound Traffic with UFW

UFW provides commands for managing incoming traffic.

### Allow an Incoming Service

Illustrative example:

```bash
sudo ufw allow 22/tcp
```

### Deny an Incoming Service

Illustrative example:

```bash
sudo ufw deny 23/tcp
```

### Allow Traffic from a Specific IP

Illustrative example:

```bash
sudo ufw allow from 192.168.1.10
```

### Inspect Existing Rules

```bash
sudo ufw status verbose
```

The inspection command does not change the firewall configuration.

---

## 8. Controlling Outbound Traffic with UFW

Outbound rules determine which connections a local machine can initiate.

### Allow Outbound HTTPS

Illustrative example:

```bash
sudo ufw allow out 443/tcp
```

### Deny Outbound FTP

Illustrative example:

```bash
sudo ufw deny out 21/tcp
```

### Inspect Outbound Policy

```bash
sudo ufw status verbose
```

Administrators should consider the effect of outbound restrictions on legitimate applications, DNS resolution, software updates, and other required services.

---

## 9. Understanding Stateful Traffic Control

A stateful firewall tracks connections.

For example:

1. Your computer starts a connection to a website.
2. The firewall recognises the new connection.
3. The website sends a response.
4. The firewall recognises the response as belonging to an established connection.
5. The response is permitted according to the applicable rules.

This is more intelligent than treating every packet as an unrelated event.

### Common Connection States

| State | Meaning |
|---|---|
| NEW | New connection attempt |
| ESTABLISHED | Existing connection |
| RELATED | Related connection |
| INVALID | Invalid or unrecognised connection state |

### Example iptables Rule

Illustrative example:

```bash
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
```

This illustrates accepting packets belonging to established or related connections.

It is not a complete firewall policy.

## 10. Understanding Network Segmentation

Network segmentation divides a larger network into smaller sections.

For example, a university might separate:

- Student network.
- Staff network.
- Administration network.
- Server network.
- Guest Wi-Fi network.

### Why Is Segmentation Important?

Suppose an attacker compromises a student's computer.

Without appropriate segmentation and filtering, the attacker might attempt to reach sensitive administrative systems.

With proper network controls, communication between these network sections can be restricted.

### Example Policy

```text
STUDENT NETWORK:
Internet access: Allowed
Administration server: Restricted
Database server: Blocked

STAFF NETWORK:
Internet access: Allowed
Administration server: Allowed for authorised users
Database server: Restricted

SERVER NETWORK:
Required application communication: Allowed
Unnecessary external access: Restricted
```

This is an example of security policy design, not a live configuration.

---

## 11. Understanding NAT and Traffic Direction

Network Address Translation (NAT) changes IP address information in network packets.

Two common types are:

### SNAT

Source Network Address Translation changes the source address.

It is commonly used when internal devices access external networks.

### DNAT

Destination Network Address Translation changes the destination address.

It can be used to direct incoming connections to an internal service.

### Example

A university may have a public IP address assigned to its gateway.

Internal computers use private IP addresses.

The gateway can translate their source addresses when they access the internet.

Important:

NAT and firewall filtering are related but different functions. NAT does not automatically provide a complete security policy.

---

## 12. IPv4 and IPv6 Traffic Control

Modern networks may use both IPv4 and IPv6.

Administrators must ensure that firewall policies cover both where both protocols are enabled.

### IPv4 Example

```text
192.168.1.10
```

### IPv6 Example

```text
2001:db8::10
```

A firewall that filters IPv4 traffic but leaves IPv6 uncontrolled may expose services through IPv6.

### Security Recommendation

- Identify whether IPv6 is enabled.
- Inspect IPv4 firewall rules.
- Inspect IPv6 firewall rules.
- Ensure both protocols follow the intended security policy.
- Avoid disabling IPv6 simply to hide an incomplete firewall configuration.

---

## 13. Common Traffic-Control Mistakes

1. Allowing all inbound connections unnecessarily.
2. Blocking required outbound connections without testing.
3. Forgetting the FORWARD chain on gateway systems.
4. Confusing local traffic with forwarded traffic.
5. Ignoring IPv6.
6. Assuming NAT replaces a firewall.
7. Applying restrictive rules without a recovery plan.
8. Failing to monitor blocked connections.
9. Allowing unnecessary communication between network segments.
10. Forgetting that traffic direction depends on the system being examined.

This lab is inspection-only. Do not change firewall rules or network settings.

### Step 1: Create Your Lab Directory


### Step 2: Inspect Network Interfaces

```bash
ip addr
```

Record:

- Interface names.
- IPv4 addresses.
- IPv6 addresses.
- Interface states.

### Step 3: Inspect Routing Information

```bash
ip route
```

This displays IPv4 routing information.

For IPv6:

```bash
ip -6 route
```

### Step 4: Inspect Listening Services

```bash
sudo ss -tulnp
```

Observe:

- TCP listeners.
- UDP listeners.
- Local addresses.
- Ports.
- Associated processes, where available.

Remember: a listening service is a potential communication entry point, but its actual network exposure also depends on its binding address, routing, and firewall policy.

For iptables:

```bash
sudo iptables -L INPUT -n -v
sudo iptables -L OUTPUT -n -v
```

